## 操作流程

1. 使用 `1001` 或 `1002` 登录，密码均为 `Box@123456`。
2. 保存航班，登记发放至少一个盒子。已有 Day2 档案也可以直接使用。
3. 打开“回收与遗失查询”，选择“盒子编号”或“座位号”，输入编号后点击“查询”或按回车。查询忽略编号大小写和首尾空格。
4. 查询结果显示姓名、座位、手机号、备用联系方式，以及发放、回收、联系和领取责任信息。
5. 收到空盒子时，直接点击“确认已归还”；盒内有手机等设备时，先勾选“盒内有遗留设备”，再确认归还。
6. 有遗留设备时，根据备用联系方式自行联系乘客，在备注中记录联系结果，点击“保存联系备注”。程序不会自动拨号或发送消息。
7. 乘客取走设备后，点击“确认设备领取”。如果修改了联系备注，必须先保存修改再确认领取；乘客直接来领取时可以不填写联系备注。
8. 可以换成另一工号继续处理。发放、回收、联系、领取分别记录当次操作人的工号和时间。
9. 关闭并重新打开程序，重新登录后查询同一盒号，确认处理结果恢复。

重新查询同一盒号、换岗或刷新表格时，未保存的联系备注会保留。修改查询条件会禁用原记录的回收和领取按钮，但保留注明盒号的备注草稿；切换到其他记录或关闭窗口时，可以选择“保存”“放弃修改”或“取消”。保存失败时保留草稿并停止切换／关闭。

登记表增加“盒子状态”和“设备状态”列，双击任意记录可以直接打开该盒子的查询详情。回收页显示已发放、已回收、待回收和待领取设备数量。

## 两种状态分别保存

| 场景 | `returned` | `deviceLeft` | `deviceClaimed` | 显示 |
| --- | --- | --- | --- | --- |
| 刚发放 | false | false | false | 待回收、待检查 |
| 收到空盒子 | true | false | false | 已归还、无遗留 |
| 收到装有设备的盒子 | true | true | false | 已归还、待领取 |
| 遗留设备已领取 | true | true | true | 已归还、已领取 |

领取后保留 `deviceLeft = true`，表示曾经出现遗留设备；不把历史改成“从未遗留”。同一盒子不能重复回收，同一设备不能重复确认领取。当前航班中盒号仍然只对应一条发放记录。

## 新代码如何配合

- `findPassenger(query, bySeat)`：根据选定类型精确查询，未登录或未找到返回 `-1`。
- `returnBox(boxNumber, deviceLeft)`：设置回收状态和回收工号／时间，发现遗留设备时进入待领取状态。
- `saveContactNote(boxNumber, note)`：仅允许修改待领取设备的联系备注，内容为 1～2000 个字符，并保存最近操作人工号／时间。
- `claimDevice(boxNumber)`：仅允许领取已回收且确有遗留的设备，保存领取操作人工号／时间。
- `validateRecovery(passenger)`：检查状态与责任信息是否一致，拒绝例如“未归还但已领取”的损坏记录。
- 窗口使用 `selectedBox` 保存当前选中盒号。查询文字或类型改变后立即取消原选中记录，防止误操作上一次查到的盒子。
- `contactBox` 单独记录备注所属盒号；`hasContactDraft()` 判断修改，`resolveContactDraft()` 在切换记录或关闭时处理草稿，避免刷新丢失输入。

所有修改仍然先生成候选档案，调用 `QSaveFile` 保存成功后才更新正式内存和界面；保存失败时保持原状态，保留输入供用户重试。

## 文件与版本

实际文件名仍为 `records.json`，目录可通过“打开数据目录”查看。Day3 写入 `version: 2`，读取同时支持 Day2 的 `version: 1`。旧格式缺少回收字段时按“尚未回收”加载，第一次成功保存时转为新格式。

新增保存回收时间、设备领取状态、联系备注及联系／领取人工号和时间。联系备注保留最近一次保存的完整文本和责任信息，不单独建立联系历史表。

文件损坏或状态不一致时，程序提示并退出；正常构建只需要 Qt Widgets，已移除指向已删除 Day2 测试文件的构建入口。

## 构建与独立演示

在 `progdes` 目录执行：

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/opt/homebrew
cmake --build build -j 4
./build/MagicBox.app/Contents/MacOS/MagicBox
```

要使用新的独立演示档案：

```bash
./build/MagicBox.app/Contents/MacOS/MagicBox --data-dir .local-data/day3
```

这会在指定目录读写 `records.json`，不改变默认目录的航班档案。Windows 继续使用 `.vscode/windows` 中的模板，修改为本机 Qt 和工具路径后构建 `build-windows/MagicBox.exe`；本次实测平台为 Mac。
