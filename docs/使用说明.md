# 神气的盒子：学生版使用说明

这是单机离线的 C++17 / Qt 6 Widgets 课程项目。支持乘务员登录与换岗、乘客登记、盒子回收、遗失设备联系、满意度评价、意见记录和手机号抽奖。

## 1. 构建与启动

### Mac

需要 CMake、C++ 编译器、Qt 6.5 或以上版本的 Widgets 模块。当前 Mac 使用 Homebrew 的 Qt 和 CMake：

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=/opt/homebrew -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel 4
open build/MagicBox.app
```

在 VS Code 中打开整个 `progdes` 文件夹，通过“终端 → 运行任务 → MagicBox: 运行 Mac”启动。Qt 程序需要用 CMake 编译整个工程。

### Windows + VS Code

1. 安装带 MinGW 套件的 Qt、与该套件匹配的 MinGW 编译器、CMake、Ninja，以及 VS Code 的 C/C++、CMake Tools 扩展。
2. 在 VS Code 打开整个 `progdes` 文件夹。
3. 备份现有 `.vscode` 配置，把 `.vscode/windows` 中的 JSON 模板复制到 `.vscode`。
4. 将模板中的 Qt、MinGW、CMake、Ninja 和 GDB 路径改为本机实际安装位置。模板版本号只是示例，各处必须使用同一套实际工具路径。
5. 执行“终端 → 运行任务 → MagicBox: 运行 Windows”，会依次配置、编译并运行 `build-windows/MagicBox.exe`。

Windows 需要从源码构建，Mac 的 `.app` 不能在 Windows 上运行。本次没有 Windows 实机验证。

## 2. 登录与换岗

| 工号 | 密码 |
| --- | --- |
| 1001 | Box@123456 |
| 1002 | Box@123456 |

输入后点击“登录 / 换岗”，也可以在密码框按回车。失败不会改变当前操作人。固定账户写在 `src/boxmanager.cpp`，用于简单课程演示。

发放、回收、保存联系备注、确认领取和抽奖分别记录实际操作人工号与时间。可以由 1001 发放，再换为 1002 回收。

## 3. 航班和登记发放

1. 登录后填写顶部航班号、日期、出发地和目的地，点击“保存航班”。
2. 在“登记发放”填写姓名、证件类型及号码、登机牌、座位、手机机型、手机号、备用联系方式、盒子编号，全部必填。
3. 点击“保存登记并发放”，保存成功后才会新增表格记录和清空表单。

身份证检查 18 位格式、出生日期和校验位；大陆手机号检查 11 位格式。备用联系方式可写电话、邮箱等文本。同一航班中盒号、证件号、座位和登机牌不能重复。

尚未登记乘客时可以修改航班并重新保存；已有乘客后锁定，防止把旧乘客挂到另一个航班。

## 4. 回收与遗失设备

1. 在“回收与遗失查询”选择盒号或座位查询，按回车或点击“查询”。也可以双击登记表中的记录跳转。
2. 收到空盒时，直接点击“确认已归还”。
3. 如果盒内还有手机，先勾选“盒内有遗留设备”，再确认归还。
4. 根据页面显示的备用联系方式联系乘客，填写联系备注并保存。
5. 乘客领取设备后，点击“确认设备领取”。

盒子归还和设备领取分开记录。已领取后仍保留“曾遗留设备”的事实；不能重复回收或重复领取。联系备注保留最新一段，最多 2000 字符，已领取后不可修改。

未保存备注在普通刷新、换岗时会保留。切换查询记录或关闭主窗口前，可以选择保存、放弃或取消；修改备注后先保存，再确认领取。

## 5. 评价和意见

1. 在“评价与意见”选择一名尚未评价的乘客。
2. 点击“进入乘客评价页”。管理窗口会隐藏，专用页面只显示评价内容。
3. 乘客可以填写意见（选填，最多 2000 字符），然后选择：1 满意、2 不满意、0 不表态。
4. 可以点击按钮，也可在意见输入框外按数字键。在意见框里输入数字只作为意见文字。
5. 成功提交后不能再评价。保存失败时保留输入，可以重试。
6. 点击“乘务员返回”，输入乘务员工号和密码。关闭窗口、按 Esc 也需要验证。验证成功后回到管理界面，再选择下一位乘客。

“未评价”是尚未提交；选择“0 不表态”是已经提交，两者分别统计。乘务员验证前若还未提交，返回不会代替乘客提交评价。

## 6. 满意度与抽奖

“满意度与抽奖”自动显示人数、三个比例和意见列表：

- 参与率 = 已评价人数 ÷ 登记人数。
- 满意率 = 满意人数 ÷ 全部已评价人数（包含不表态）。
- 已表态满意率 = 满意人数 ÷（满意人数 + 不满意人数）。

分母为 0 显示“暂无数据”。双击意见列表可以查看完整意见。

所有已提交评价的乘客都可参加抽奖，包括选择 0 的乘客。同一手机号只算一个机会，本航班已中奖号码不再参加后续抽取。抽奖人数默认 1，可调整；候选不足不会进行部分抽取。

点击“抽取并保存中奖号码”，结果保存成功后出现在表格和底部提示中。中奖人工号和时间一起保存，重启后规则不变。新航班重新计算本航班奖池。

## 7. 更换航班

1. 完成当前航班全部盒子回收，以及全部遗留设备领取。
2. 点击右下角“新建航班”。
3. 填写新航班号、日期、出发地、目的地，点击“备份并新建”。航班号和日期不能同时与当前相同。
4. 系统先备份旧航班，再保存新的空乘客档案；成功后返回登记页。

旧档案在数据目录的 `history/日期_唯一编号/records.json`，保留乘客、回收、评价、意见和中奖信息。新航班可以复用原盒号。没有全部评价也可以开始新航班，因为评价允许乘客不参与。

当前是一个活动航班，没有复杂的历史航班切换界面。可以通过“打开数据目录”查看历史文件。要在程序里单独查看一份历史档案，可退出程序后用下面的参数启动，把路径替换为该备份文件所在目录；程序对这个指定目录的操作会写回该目录，需要保留原备份时先复制一份：

```sh
./build/MagicBox.app/Contents/MacOS/MagicBox --data-dir "历史档案的独立副本目录"
```

## 8. 数据与示例

默认数据由 Qt 的应用数据目录保存，具体路径点击“打开数据目录”查看，文件名为 `records.json`。启动时也支持 `--data-dir` 自定义目录。

Day4 写入版本 3，可读取版本 1、2、3。所有业务先写入文件，成功后才更新内存和界面；保存失败可以重试。文件损坏时启动会提示并退出，不会自动清空原数据。请保留出错文件后检查或恢复备份。

样例位于 `examples/day4/records.json`，所有姓名、证件、电话和联系备注仅用于演示。推荐复制到项目的独立演示目录：

```sh
mkdir -p .local-data/day4-demo
cp examples/day4/records.json .local-data/day4-demo/records.json
./build/MagicBox.app/Contents/MacOS/MagicBox --data-dir .local-data/day4-demo
```

重新复制会重置这个演示目录。正式默认目录不受影响。

样例包含 5 名乘客：2 满意、1 不满意、1 不表态、1 未评价；参与率 80.0%，满意率 50.0%，已表态满意率 66.7%。已评价者有重复手机号，所以初始只有 3 个去重抽奖候选。

## 9. 对照题目演示

1. 用 1001 登录，登记乘客并重启，证明账户验证、字段检查及文件保存。
2. 换为 1002，按盒号或座位回收，证明不同乘务员分别负责。
3. 查询 BOX003，查看备用联系方式，保存联系备注，确认设备领取，证明遗失手机联系流程。
4. 给 BOX004 提交评价及意见，尝试重复评价，展示提交限制。
5. 展示统计中“未评价”和“0 不表态”的区别，以及意见汇总。
6. 抽奖后重启，再抽奖，证明手机号去重和已中奖排除；输入过多抽奖人数，展示候选不足提示。
7. 回收 BOX001 并处理完 BOX003 后，新建航班，展示历史备份及盒号复用。

## 10. 源码入口

| 文件 | 职责 |
| --- | --- |
| CMakeLists.txt | C++17、Qt Widgets 和应用构建 |
| src/main.cpp | 加载数据、解析目录参数、启动窗口 |
| src/models.h | 账户、乘客、航班、统计及中奖结构体 |
| src/validation.h / .cpp | 乘客、航班和回收状态校验 |
| src/datastore.h / .cpp | JSON 加载、安全保存及历史备份 |
| src/boxmanager.h / .cpp | 登录和各项业务规则 |
| src/mainwindow.h / .cpp | 四个管理页面和按钮交互 |
| src/surveydialog.h / .cpp | 乘客专用评价及乘务员返回验证 |
| docs/day1.md 至 day4.md | 每日分工安排、开发范围和验收记录 |

普通构建只需要 Qt Widgets，不需要 Qt Test。当前交付采用单实例演示，运行中不要让多个程序实例同时修改同一个数据目录。
